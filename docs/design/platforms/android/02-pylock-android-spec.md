# Android — `pylock.android.toml` Schema

> **Status: design.** Companion to [pyproject-android](01-pyproject-android.md).

`pylock.android.toml` is the **reproducibility artifact** generated by
`kivyforge lock` from the user's `pyproject.toml` for the Android target. It pins
the exact per-ABI Python wheels, the exact python.org Android runtime (per ABI),
the exact native `.aar`/`.jar` archives, and the resolved Gradle/Maven
dependencies a build will use — by URL and SHA-256 wherever a content hash is
meaningful — and records the manifest/Gradle wiring intent.

The format **conforms to PEP 751** (`pylock.toml`). PEP 751 permits per-tool
extension tables under `[tool.<name>]`; kivyforge stores its build-specific bits
(the Android runtime, native libs, Gradle pins, per-wheel provenance) inside a
single `[tool.kivyforge]` table. The standard `[[packages]]` array stays
consumable by PEP 751-aware installers; everything kivyforge needs lives under the
tool table.

The matching lock for another target of the same `pyproject.toml` is
`pylock.<platform>.toml` — **the platform is identified by the filename**, not a
discriminator field. See the [generalized lockfile concept](../../common/03-lockfile-concept.md).

## Design principles

- **PEP 751 conformant.** `[[packages]]` is a valid PEP 751 lock any PEP 751-aware consumer can read. Selecting and installing the correct per-ABI Android wheels is performed by kivyforge itself (see "Resolution semantics"), not delegated to a generic installer.
- **Pinned by URL and content hash.** Every fetchable artifact — wheel, runtime tarball, `.aar`/`.jar` — has a URL (or repo-relative `path`) and a SHA-256 the toolchain verifies before use.
- **One package, multiple ABIs.** A compiled Python wheel appears as multiple `[[packages.wheels]]` entries — one per `android_<api>_<abi>` slice the build targets.
- **Gradle/Maven: Gradle fetches, but every artifact is still hash-pinned.** Like iOS's SPM channel, Gradle owns the resolve/fetch/compile lifecycle for Maven coordinates. Unlike a bare version lock, kivyforge pins the **full resolved transitive graph with a SHA-256 per artifact** in the lock (`[[tool.kivyforge.gradle.resolved]]`) and, at build time, materializes Gradle's `gradle.lockfile` **and** `verification-metadata.xml` from it — so Gradle rejects any artifact whose bytes don't match. Integrity is therefore the same coordinate/URL + SHA-256 discipline as every other channel; kivyforge only delegates the *download* to Gradle (see "Gradle/Maven pins").
- **Generated, not hand-edited.** Users edit `pyproject.toml`; `kivyforge lock` regenerates the lock.
- **PEP 751 + kivyforge schema versions are independent.** PEP 751 owns `lock-version`; `[tool.kivyforge].schema_version` evolves the tool extensions separately.

## Filename

`pylock.android.toml`, sibling to `pyproject.toml`.

## Top-level structure

```toml
# Required by PEP 751.
lock-version = "1.0"
created-by = "kivyforge"
requires-python = ">=3.14"
extras = []
dependency-groups = []
default-groups = []

# Standard PEP 751 package entries; readable by any PEP 751-aware installer.
[[packages]]
# Repeatable. Each entry pins one Python package (with per-ABI wheels).

# kivyforge extension: python.org Android runtime (per ABI), native libs,
# Gradle pins, per-wheel provenance, source-pyproject hash, schema versions.
[tool.kivyforge]
```

## Standard PEP 751 fields

| Field | Type | Set by `kivyforge lock` to |
|-------|------|----------------------------|
| `lock-version` | string | `"1.0"`. kivyforge refuses a `lock-version` major higher than it understands. |
| `created-by` | string | `"kivyforge"`. |
| `requires-python` | string | Carried from `[project].requires-python`, falling back to `">=3.14"` (Android's CPython Tier-3 floor). |
| `extras` | array | `[]` — Android does not currently consume `[project].optional-dependencies`. |
| `dependency-groups` | array | `[]`. |
| `default-groups` | array | `[]`. |

## `[[packages]]` — Python wheels (PEP 751 standard)

Every Python package the build needs is one `[[packages]]` entry:

```toml
[[packages]]
name = "kivy"
version = "2.3.1"
requires-python = ">=3.9"

[packages.tool.kivyforge]
direct_requirement = true

[[packages.wheels]]
name = "Kivy-2.3.1-cp314-cp314-android_24_arm64_v8a.whl"
path = "wheels/Kivy-2.3.1-cp314-cp314-android_24_arm64_v8a.whl"
hashes = { sha256 = "abc123..." }

[[packages.wheels]]
name = "Kivy-2.3.1-cp314-cp314-android_24_x86_64.whl"
path = "wheels/Kivy-2.3.1-cp314-cp314-android_24_x86_64.whl"
hashes = { sha256 = "def456..." }
```

The PEP 751 fields kivyforge emits per package are as for iOS
([pylock-ios-spec §"`[[packages]]`"](../ios/02-pylock-ios-spec.md#packages--python-wheels-pep-751-standard)):
`name`, `version`, `requires-python`, `dependencies`, `marker`, and exactly one
source type. For Android that source type is **always `wheels`** — `sdist`,
`vcs`, and `directory` all imply an on-host compile step, which kivyforge does not
have for Android (see [artifact-distribution-android](03-artifact-distribution-android.md)).
A wheel may still be sourced locally via a per-wheel `path` (the canonical
vendored-Kivy case).

Per-wheel fields (PEP 751): `name` (the `android_<api>_<abi>` tag is parsed back
out for ABI routing), `upload-time`, `url` *or* `path` (exactly one), `hashes`
(SHA-256, required — computed from the file for `path` wheels), `size`.

### Multi-ABI wheels

A compiled-extension wheel appears as **multiple `[[packages.wheels]]` entries in
the same `[[packages]]` block** — one per `[tool.kivy.android].abis` entry (by
default `android_24_arm64_v8a` and `android_24_x86_64`). `kivyforge build`
installs each ABI slice into its own per-ABI staging directory and lays the
resulting `.so`s into `jniLibs/<abi>/`.

### Pure-Python wheels

Pure-Python wheels have a single `py3-none-any` entry (installed once, shared
across ABIs).

### Locally built wheels (`path`)

Identical to the [iOS `path` mechanism](../ios/02-pylock-ios-spec.md#locally-built-wheels-path):
a relative `path` is resolved relative to `pylock.android.toml`, must use POSIX
separators, must not be absolute or escape the project directory, and is still
hash-pinned. **This is the canonical delivery path for the Kivy 2.3.1 and pyjnius
Android wheels** until they are published to PyPI — the author cross-builds them
with `cibuildwheel` and vendors them in the repo (`wheels/`).

### Per-package kivyforge metadata: `[packages.tool.kivyforge]`

```toml
[packages.tool.kivyforge]
direct_requirement = true
source_index = "https://wheels.example.com/simple"
```

Same fields as iOS: `direct_requirement` (bool) and `source_index` (the index a
wheel resolved from; omitted means PyPI). Invisible to stock pip.

## `[tool.kivyforge]` — top-level extension

```toml
[tool.kivyforge]
schema_version = 1
kivyforge_version = "3.0.0"
generated_at = "2026-08-01T00:00:00Z"
pyproject_sha256 = "e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855"
tool_kivy_android_schema_version = 1
sdl = 2

[[tool.kivyforge.python_android]]
# Repeatable — one per ABI.

[[tool.kivyforge.android_libs]]
# Repeatable — one per .aar/.jar.

[tool.kivyforge.gradle]
# Maven coordinate pins + the resolved transitive graph (per-artifact SHA-256).

[[tool.kivyforge.include_files]]
# Repeatable — one per staged config file (SHA-256 drift pin).
```

### `[tool.kivyforge]` scalar fields

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `schema_version` | integer | yes | This lockfile's `[tool.kivyforge]` schema version (independent of PEP 751's `lock-version` and the pyproject overlay schema). |
| `kivyforge_version` | string | yes | Version of `kivyforge` that generated the lock. |
| `generated_at` | string | yes | ISO 8601 UTC timestamp. |
| `pyproject_sha256` | string | yes | SHA-256 of the source `pyproject.toml` at lock time. `kivyforge build` recomputes and errors on mismatch (drift detection). |
| `tool_kivy_android_schema_version` | integer | yes | Echoes `[tool.kivy.android].schema_version` from the source pyproject. |
| `sdl` | integer | yes | The SDL generation this lock targets (`2` or `3`), echoed from `[tool.kivy.android].sdl`. Recorded because it governs which SDL native library the bootstrap load order and the pyjnius runtime resolver expect (see [bootstrap-android](05-bootstrap-android.md)). |

### `[[tool.kivyforge.python_android]]` — the runtime, per ABI

python.org publishes the Android CPython runtime as a **per-ABI relocatable
artifact** (aarch64 + x86_64), the Android analog of the iOS `Python.xcframework`.
Because it is per-ABI (not a single fat artifact like the xcframework), it is a
repeating table — one entry per targeted ABI:

```toml
[[tool.kivyforge.python_android]]
version = "3.14.6"
abi = "arm64_v8a"
url = "https://www.python.org/ftp/python/3.14.6/python-3.14.6-android-aarch64.tar.gz"
sha256 = "..."
min_api = 24

[[tool.kivyforge.python_android]]
version = "3.14.6"
abi = "x86_64"
url = "https://www.python.org/ftp/python/3.14.6/python-3.14.6-android-x86_64.tar.gz"
sha256 = "..."
min_api = 24
```

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `version` | string | yes | The CPython version pinned for this build. |
| `abi` | string | yes | `arm64_v8a` or `x86_64`. |
| `url` *or* `path` | exactly one | The resolved download URL on python.org (constructed by `kivyforge lock` from the requested version + ABI), or a repo-relative vendored path. |
| `sha256` | string | yes | Verified before use. python.org also signs releases with Sigstore; `kivyforge build` may verify the signature in addition (future enhancement). |
| `min_api` | integer | no | The minimum Android API the runtime supports, read from the artifact metadata. `kivyforge lock` errors if `[tool.kivy.android].min_sdk` is below it. |

> **URL pattern is resolved, not hardcoded.** The exact python.org Android
> release-artifact filename/layout is read at lock time from the release's file
> list and recorded verbatim; the pattern above is illustrative. This mirrors how
> the iOS provider derives the `Python-iOS-XCframework` URL. See
> [artifact-distribution-android §"Distribution channel 2"](03-artifact-distribution-android.md#distribution-channel-2-the-pythonorg-android-runtime).

### `[[tool.kivyforge.android_libs]]` — native `.aar`/`.jar`

Each entry pins one prebuilt Android library archive declared under
`[tool.kivy.android.native.aars]` / `[tool.kivy.android.native.jars]`:

```toml
[[tool.kivyforge.android_libs]]
name = "MyVendorSDK"
kind = "aar"
version = "3.1.0"
url = "https://vendor.example.com/sdk/MyVendorSDK-3.1.0.aar"
sha256 = "..."

[[tool.kivyforge.android_libs]]
name = "legacyutil"
kind = "jar"
version = "1.4.0"
path = "libs/legacyutil-1.4.0.jar"
sha256 = "..."
```

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `name` | string | yes | Matches the `[tool.kivy.android.native.*]` key. |
| `kind` | string | yes | `"aar"` or `"jar"`. |
| `version` | string | yes | Resolved version. |
| `url` *or* `path` | exactly one | Download URL or repo-relative vendored path. |
| `sha256` | string | yes | Verified before staging into the Gradle project's `libs/`. Computed from the file for `path` artifacts. |

This array is empty in a vanilla Kivy app.

### `[tool.kivyforge.gradle]` — Maven/Gradle pins

> **Realized vs designed (v1).** The resolved transitive graph with a per-artifact
> SHA-256 **is** recorded in the lock under `[[tool.kivyforge.gradle.resolved]]`
> (the committed audit trail; `kivyforge lock` runs Gradle once via the vendored
> wrapper to produce it). What v1 does **not** do is materialize a Gradle-enforced
> `verification-metadata.xml` into the generated project: Gradle's verification is
> **global** — it would require pinning the entire AGP build classpath (aapt,
> transforms, androidx, …), not just the app's declared Maven deps, so a partial
> file makes every build fail on unlisted artifacts. The app's coordinates are
> version-pinned in `app/build.gradle`; Gradle-*enforced* SHA verification of them
> is deferred to a future full-classpath resolve. The lock's SHA-256 record stands
> as the reproducibility/audit source of truth today.

For `[tool.kivy.android.gradle].dependencies` (Maven coordinates). Gradle owns
resolution; kivyforge pins the coordinate set and references a generated Gradle
**dependency-lock** so transitive resolution is reproducible:

```toml
[tool.kivyforge.gradle]
repositories = ["https://maven.example.com/releases"]
dependencies = [
    "androidx.work:work-runtime:2.9.1",
    "com.google.android.gms:play-services-location:21.3.0",
]

# Full resolved transitive graph, pinned by content hash. kivyforge regenerates
# gradle.lockfile + gradle/verification-metadata.xml from these entries at build
# time, so nothing reproducibility-relevant lives in the disposable <app>-android/.
[[tool.kivyforge.gradle.resolved]]
coordinate = "androidx.work:work-runtime:2.9.1"
artifacts = [
    { name = "work-runtime-2.9.1.aar", sha256 = "..." },
    { name = "work-runtime-2.9.1.module", sha256 = "..." },
]

[[tool.kivyforge.gradle.resolved]]
coordinate = "androidx.work:work-runtime-ktx:2.9.1"   # pulled in transitively
artifacts = [
    { name = "work-runtime-ktx-2.9.1.aar", sha256 = "..." },
]
```

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `dependencies` | array | no | The declared (direct) coordinates, carried verbatim from the overlay for auditability. |
| `repositories` | array | no | Extra Maven repos (beyond `google()`/`mavenCentral()`). |
| `resolved` | array of tables | no | The full transitive graph Gradle resolved: one entry per module `coordinate`, each listing the downloaded `artifacts` (`name` + `sha256`). This is the committed reproducibility record; `kivyforge build` regenerates `gradle.lockfile` (versions) and `gradle/verification-metadata.xml` (hashes) from it into the project. Omitted when no Maven deps are declared. |

This is the **SPM-parallel channel**: Gradle performs the download and compile,
but every resolved artifact is pinned by SHA-256 under `resolved` and enforced by
the `verification-metadata.xml` kivyforge materializes — so the integrity
guarantee matches channels 1–3. The generated Gradle files (`gradle.lockfile`,
`verification-metadata.xml`) exist only inside the regenerated `<app>-android/`
and are derived from this table on every build, so the committed lock stays the
single source of truth (a Gradle lock can never end up stranded inside a
`.gitignore`-d project). Rationale in
[artifact-distribution-android §"Distribution channel 4"](03-artifact-distribution-android.md#distribution-channel-4-gradlemaven-dependencies).

### `[[tool.kivyforge.include_files]]` — copied config-file pins

For `[[tool.kivy.android.include_files]]`. Each staged source is hashed so a
changed config file (e.g. `google-services.json`) is caught by drift detection
even though it never enters a wheel or the Python bundle:

```toml
[[tool.kivyforge.include_files]]
source = "config/google-services.json"
dest = "app"
sha256 = "..."
```

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `source` | string | yes | Repo-relative source path from the overlay entry. |
| `dest` | string | yes | Destination directory (relative to `<app>-android/`), carried verbatim. |
| `sha256` | string | yes | SHA-256 of the source file, verified before the Stage-step copy. (A directory source expands to one entry per file.) |

This array is empty unless `include_files` is declared.

## Resolution semantics

`kivyforge lock`:

1. Parses `pyproject.toml`; validates `[project]`, `[tool.kivy]`, `[tool.kivy.android]`.
2. Resolves the python.org Android runtime for each `[tool.kivy.android].abis` entry, reading the release file list to pin per-ABI `url` + `sha256` + `min_api` into `[[tool.kivyforge.python_android]]`. Errors if `min_sdk < min_api`.
3. For each `[project].dependencies` entry:
   - Invokes pip in resolve-only mode with the right Android platform tags per ABI (`--platform android_<api>_<abi>`, `--python-version`, `--abi`, `--implementation`, `--only-binary=:all:`), consulting PyPI plus any `extra_index_urls` / `find_links`.
   - **Pins every targeted ABI slice, host-independent.** For every compiled package, resolve and pin a wheel per targeted ABI so the committed lock is reproducible on any host/CI. Pure-Python packages resolve to a single `py3-none-any` entry.
   - **Two fail-fast conditions at lock time** (mirroring iOS):
     - **Missing ABI.** A compiled package lacking a wheel for any targeted `android_<api>_<abi>` slice is rejected — a partially-pinned package would build for one ABI and be absent for another. (Narrowing `abis` correspondingly narrows what counts as "missing".)
     - **Inconsistent version across ABIs.** Each ABI is a separate pip resolution; if they disagree on version (e.g. the arm64 wheel published before the x86_64 one), `lock` refuses it and names the conflicting versions, rather than merging mismatched binaries into one `version` field. Re-lock once upstream publishes the lagging slice.
   - Records direct + transitive wheels as `[[packages]]` blocks (pinning `url` for hosted, or repo-relative `path` for vendored — the Kivy/pyjnius case). Marks direct requirements.
4. For each `[tool.kivy.android.native.*]` entry: reads the artifact (download for a URL, local read for a path), computes its SHA-256, records `[[tool.kivyforge.android_libs]]`.
5. For `[tool.kivy.android.gradle]`: emits a scratch `build.gradle` with the declared coordinates/repos and runs Gradle with dependency locking **and** verification (`--write-locks --write-verification-metadata sha256`). It parses the resulting transitive graph and per-artifact SHA-256 and records them under `[[tool.kivyforge.gradle.resolved]]` — the values are **embedded in the lock**, not referenced as a file inside the generated project. (Requires a reachable JDK+Gradle at lock time; skipped when `dependencies` is empty.)
6. For each `[[tool.kivy.android.include_files]]` source (expanding directories): reads the file, computes its SHA-256, records `[[tool.kivyforge.include_files]]`.
7. Writes `pylock.android.toml` atomically (tempfile, fsync, rename).

Entry order is **deterministic** (sorted by name, then version, then platform
tag) so diffs across `lock` runs show only real changes.

## Drift detection

`kivyforge build` recomputes `pyproject_sha256`; a mismatch aborts with:

```
Error: pyproject.toml has changed since pylock.android.toml was generated.
  Run: kivyforge lock
  Or:  kivyforge build --no-verify-lock   (not recommended)
```

## Hash verification

Every artifact download (wheel, runtime tarball, `.aar`/`.jar`) is verified
against its declared `sha256`; a mismatch aborts with the artifact name, URL,
expected/actual hash, and a tamper hint. Maven artifacts are verified **by Gradle
against the `verification-metadata.xml` kivyforge materializes from
`[[tool.kivyforge.gradle.resolved]]`** — mandatory whenever Maven dependencies are
declared, so a mutated artifact at a pinned version is rejected too. The download
is Gradle's; the SHA-256 pin is kivyforge's.

## Schema evolution

| Version | Owner | Bump when |
|---------|-------|-----------|
| `lock-version` | PEP 751 | Upstream PEP revision. |
| `[tool.kivyforge].schema_version` | kivyforge | Backward-incompatible change under `[tool.kivyforge]`. |
| `[tool.kivyforge].tool_kivy_android_schema_version` | kivyforge (echoed) | Records the source `[tool.kivy.android].schema_version`. |

## Artifact-to-project-folder mapping (cross-reference)

Normative in [artifact-distribution-android](03-artifact-distribution-android.md), recapped:

- `[[packages]]` wheels are installed per-ABI; their `.so` extension modules land in `app/src/main/jniLibs/<abi>/` and their pure-Python content in the staged Python bundle (asset). Wheel-embedded native libs (flat `.libs/`, ABI from the wheel tag) also land in `jniLibs/<abi>/`.
- `[[tool.kivyforge.python_android]]` is extracted per ABI into the runtime staging area, then laid into `jniLibs/<abi>/` + the Python bundle.
- `[[tool.kivyforge.android_libs]]` (`.aar`/`.jar`) are staged into `<app>-android/app/libs/` and referenced by `app/build.gradle`.
- `[tool.kivyforge.gradle]` coordinates are emitted into `app/build.gradle`; Gradle resolves them against the `gradle.lockfile` + `verification-metadata.xml` kivyforge materializes from `[[tool.kivyforge.gradle.resolved]]`.
