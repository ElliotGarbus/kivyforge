6. **The macOS `.app` is `drwxr-xr-x`**, not `drwx------`, after `build` and

## Task 2 — code: the rest of the docs-review issue list

The docs review on 2026-09-23 listed seven code issues. Items 1–5 are done
(PRs #17 and #19). Items 6 and 7 are **not started**. None need a Mac, but

### Item 6 — the `buildozer.spec` map printed by `init` is stale

`kivyforge/cli/init.py`: the `[app]` key map starts at line 64, and the
message is built by `_buildozer_migration_message` (raised at line 181 when a
`buildozer.spec` exists and `pyproject.toml` does not). It names the wrong
Gradle and archive keys, and says app-side Java is unsupported, which is no
longer true. Check each mapping against the Android overlay reference
(`docs/guides/reference/pyproject/android.md`) and the loader, and pin the map
with a test so it cannot drift again.

### Item 7 — smaller items

- **Read `pyproject.toml` as `utf-8-sig`.** A file saved with a BOM fails with
  "invalid TOML: Invalid statement (at line 1, column 1)". It was hit while
  writing a test (PowerShell's `-Encoding utf8` writes a BOM). Read sites:
  `config/loader.py:142`, `cli/_platform.py:41`, `cli/lock.py:180`,
  `cli/init.py:344/363/388`, `platforms/android/cli.py:1116`. **Watch out:**
  the lock stores `pyproject_sha256`, so decide whether the hash covers the
  bytes or the decoded text, and make sure every site agrees. Otherwise a
  BOM'd file locks and then reads as drifted.
- **Remove the Developer ID from the dice-roller example.**
  `examples/desktop/dice-roller/pyproject.toml:42-43` ships
  `identity = "Developer ID Application: ELLIOT DREW GARBUS (R5PKSQLUZY)"`,
  so the desktop quickstart's `package` step fails for anyone else; the
  quickstart currently tells readers to delete the table. Removing it means
  re-checking the quickstart text and any CI job that packages dice-roller
  signed. The dice-roller lock is gitignored, so there is no lock to commit.
- **`doctor` does not check for Pillow** when icons are configured. Pillow is
  imported lazily in `platforms/windows/icons.py:57`,
  `platforms/linux/icons.py:115/122` and `platforms/android/splash.py:250`,
  and a missing Pillow surfaces only mid-build. Add a check per platform that
  FAILs (or WARNs, if a fallback exists; Linux has a no-Pillow placeholder
  icon) when `icons.source` is set and `PIL` does not import, with the
  matching `kivyforge[<platform>]` extra in the hint.
- **`cli/_common.py:134` suggests `kivyforge init`** to create a missing
  `pyproject.toml`, but `init` refuses to create one. Reword it to say what
  `init` actually needs.

## The gate, and conventions

Before any PR, run the four CI commands from `AGENTS.md` (pytest, which fails
under 80% coverage; `ruff check`; `ruff format --check`; `pyright`), plus
`mkdocs build --strict` when docs change. Merge PRs with a merge commit and
delete the branch. User-facing strings must encode in cp1252, spawned tools
get `stdin=DEVNULL` (except `run`'s app launch), and signing secrets stay out
of `pyproject.toml`.
