### Item 7 — smaller items

- **Read `pyproject.toml` as `utf-8-sig`.** A file saved with a BOM fails with
  "invalid TOML: Invalid statement (at line 1, column 1)". It was hit while
  writing a test (PowerShell's `-Encoding utf8` writes a BOM). Read sites:
  `config/loader.py:142`, `cli/_platform.py:41`, `cli/lock.py:180`,
  `cli/init.py:344/363/388`, `platforms/android/cli.py:1116`. **Watch out:**
  the lock stores `pyproject_sha256`, so decide whether the hash covers the

  BOM'd file locks and then reads as drifted.

  `examples/desktop/dice-roller/pyproject.toml:42-43` ships

- **`doctor` does not check for Pillow** when icons are configured. Pillow is

### Task 3 — on the Mac, from 2026-10-01: iOS `strip_source` may become testable

**This date falls inside the time away.** PEP 790 schedules CPython 3.15.0
final for 2026-10-01. Every iOS example pins `3.15.0b4`
(`examples/mobile/*/pyproject.toml`), and that pin is the *only* reason iOS
`strip_source` has never run: `package -p ios` degrades to shipping source
with "no final CPython 3.15 found" (test-matrix §7, 2026-09-14). It is also
why `ios_app_problems` has no stripped/`.pyc`-magic check, which is the
highest-value check on every other platform (see
[`ios-t3-checks-prompt.md`](ios-t3-checks-prompt.md), "Scope constraint").

**Check, do not assume**, that both of these exist before starting:

1. a CPython 3.15.0 **final** on the Mac (the byte-compiler), and
2. python.org's iOS `Python.xcframework` for 3.15.0 final (what the lock
   pins).

If both exist: re-pin one gate example (`hello-kivy`) to the final, run
`package -p ios`, confirm it byte-compiles instead of degrading, and extend
`ios_app_problems` with the stripped and magic checks the other four
platforms have. **Every check must be shown to fire** against a bad input,
not only to pass a good one. `hello-kivy` tracks its lock on purpose
(`docs/design/common/03-lockfile-concept.md`, "Example-repo lock policy"), so
**diff and report a changed `pylock.ios.toml`; do not commit it** without
asking. Log a test-matrix §7 row either way. "3.15.0 was not out yet" is a
result too.

**Nothing breaks on 2026-10-01 if this is skipped.** The only CI job that
used a floating 3.15 (`android_windows_host`'s pre-release, for the resolver
rejection test) was pinned to `3.15.0-rc.2` on 2026-09-24 so that it would
not. The pin needs replacing only if the Windows runner image starts shipping
a 3.15 final, and the test's failure message says so.

### Task 4 — on the Mac: Android has never been built on a macOS host

Android is built on ubuntu (`android_gradle`) and Windows
(`android_windows_host`) in CI, and on the Windows dev box by hand. **Never
on macOS**, although `kivyforge capabilities` lists it as a supported host.
The first run is the whole task: `doctor -p android`, then `package -p
android --abi arm64_v8a` on `examples/mobile/hello-android` (it tracks its
lock; do not commit a changed one), then the three T3 drivers against the
APK exactly as `android_gradle` runs them (`tests/platforms/android/`, with
`--android-stripped`). Record the SDK/NDK/JDK versions in a §7 row. Watch the
byte-compile resolver: on macOS it searches for `python3.14` rather than the
Windows `py` launcher, and it logs which interpreter it picked.

### Task 5 — on the Mac, one command: the macOS runtime's case collisions

test-matrix §5.6 fixed case-only path collisions in runtime archives. Every
Linux runtime has 25, all in `python/share/terminfo`. The macOS runtime was

## The gate, and conventions

Before any PR, run the four CI commands from `AGENTS.md` (pytest, which fails
under 80% coverage; `ruff check`; `ruff format --check`; `pyright`), plus
`mkdocs build --strict` when docs change. Merge PRs with a merge commit and
delete the branch. User-facing strings must encode in cp1252, spawned tools
get `stdin=DEVNULL` (except `run`'s app launch), and signing secrets stay out
of `pyproject.toml`.
